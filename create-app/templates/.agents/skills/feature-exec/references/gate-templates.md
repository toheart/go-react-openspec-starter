# Gate 模板

## 通用流程

1. 先汇总上一阶段的关键结果。
2. 非信任模式下，给用户明确选项：通过、修改、停止。
3. 非信任模式下，输出选项后必须停止本轮响应，等待用户下一条消息。
4. 非信任模式下，在用户明确选择“通过”之前，禁止调用 `set-gate ... passed`、禁止进入下一阶段、禁止归档。
5. 信任模式下，输出 `[信任通过]` 与理由后继续。
6. 如果测试存在失败项，不能在信任模式下强行通过 `gate-test`。

## gate-code

摘要至少覆盖：

- 后端审查结论
- 前端审查结论
- 是否存在阻断项
- 需要用户判断的事项

非信任模式参考输出：

```text
## Gate: 代码审查确认

<后端审查摘要>
<前端审查摘要>
<阻断项、已修复项与剩余风险>

选项：
1. 通过，进入测试写作
2. 回到实现/修复阶段
3. 停止本次变更

请回复选项编号或明确指令。
```

输出该模板后必须停止，不得调用 `set-gate execution <change-name> gate-code passed`。

## gate-test-code

摘要至少覆盖：

- `test-writer` 新增或更新的测试文件
- 覆盖到的 `test-plan.md` 场景
- `go test` 结果

非信任模式参考输出：

```text
## Gate: 测试代码确认

<测试代码摘要>
<覆盖场景摘要>
<自动化测试结果>
<剩余风险>

选项：
1. 通过，进入 QA 验收
2. 回到测试写作阶段修复
3. 停止本次变更

请回复选项编号或明确指令。
```

输出该模板后必须停止，不得调用 `set-gate execution <change-name> gate-test-code passed`。

## gate-test

摘要至少覆盖：

- `qa-report.md` 的通过 / 失败 / 跳过统计
- 失败用例列表
- 是否满足归档条件

非信任模式参考输出：

```text
## Gate: 测试结果确认

<QA 与测试固化摘要>

选项：
1. 通过，进入归档
2. 回到实现阶段修复
3. 停止本次变更

请回复选项编号或明确指令。
```

输出该模板后必须停止，不得调用 `set-gate execution <change-name> gate-test passed` 或 `openspec archive`。

信任模式参考输出：

```text
## [信任通过] Gate: 测试结果确认

<QA 与测试固化摘要>

通过理由：测试全部通过，产物齐备，可以进入归档。
```
